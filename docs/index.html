    01 先抄下现用光猫的接入参数

    1. 暂时保持原网络和光纤不动，打开现用光猫 http://192.168.1.1。记录标签的准确型号，不用“青春版”商品名判断 PON 制式。
    2. 在状态/PON/注册信息、WAN/互联网连接页面截图，填写包内 docs/接入参数记录表.txt。能导出配置就再导出一份。
    3. 记录实际 PON 模式、认证方式与认证字段、业务 VLAN/优先级、PPPoE 或 DHCP、IPv6；如果由外接路由器拨号，宽带账号密码在那台路由器或运营商处取得。

    通过后：现网认证、上网方式和所需参数已离线保存，再处理新 XG。

    不符合时：看不到密码、认证方式或线路模式时先记录“未知”；可以先备份新 XG，但不要在缺关键参数时切换主网。

    05 开启新 XG Telnet，取得 root

    2. 打开 01-Open-Telnet.cmd，PuTTY 选择 Telnet、端口 23、主机为新 XG。用标签普通账号/密码登录，密码输入不显示字符。
    3. 执行 id。不是 uid=0 时，常见 user 批次执行 su user_ftp，输入标签普通密码，再执行 id。

    07 把新 XG 全部原厂分区备份到 U 盘

    1. 插入放好两个 .sh 的 U 盘，等约 15 秒。先复制“定位 U 盘”，看到 USB_READY 后，再复制“执行备份”。
    2. 等待逐个 Reading mtdN 完成，不关终端、不拔盘。成功应出现 Backup stored on USB，保存它显示的完整目录。
    3. 备份结束后执行 sync 和 umount；卸载成功再拔盘。

    通过后：U 盘得到整套 xg040gmd-stock-... 目录，并含 COMPLETE.txt、分区表、设备端校验单和日志。

    不符合时：STOP、FAILED.txt、dd 读错或没有 USB_READY 都不能当作成功；不要改到 /tmp 或添加 conv=noerror。

    在新 XG root Shell：定位 U 盘

    XG_USB_ROOT=''
XG_USB_COUNT=0
while read XG_SRC XG_MNT XG_FS XG_OPTS XG_REST; do
  case "$XG_SRC" in /dev/sd*|/dev/mmcblk*) ;; *) continue ;; esac
  if [ -f "$XG_MNT/backup-stock-to-usb.sh" ] && [ -f "$XG_MNT/collect-device-info.sh" ]; then
    XG_USB_ROOT="$XG_MNT"
    XG_USB_COUNT=$((XG_USB_COUNT + 1))
  fi
done < /proc/mounts
if [ "$XG_USB_COUNT" = 1 ]; then
  export XG_USB_ROOT
  printf 'USB_READY: %s\n' "$XG_USB_ROOT"
else
  XG_USB_ROOT=''
  printf 'STOP: matching USB mounts=%s\n' "$XG_USB_COUNT"
fi

    在新 XG root Shell：仅 USB_READY 后执行备份

    if [ -z "$XG_USB_ROOT" ]; then
  printf 'STOP: run USB detection first\n'
else
  XG_INFO_LOG="$XG_USB_ROOT/device-info-$(date +%Y%m%d-%H%M%S).txt"
  sh "$XG_USB_ROOT/collect-device-info.sh" > "$XG_INFO_LOG" 2>&1
  sh "$XG_USB_ROOT/backup-stock-to-usb.sh" "$XG_USB_ROOT"
fi

    在新 XG root Shell：仅备份已经结束后安全卸载

    sync
umount "$XG_USB_ROOT"

    busy 时先关闭访问 U 盘的 FTP/其他窗口再重试，不强制拔盘。脚本只读 MTD，输出到真实 USB/SD 挂载点；所有重叠 MTD 视图都保留，不能拼接成整片镜像。

    16 登录 PonWrt，填写 PON 参数

    1. 电脑改回自动获取 IP/DNS，拔插网线，用 ipconfig 查看新地址；通常打开 http://192.168.1.1。确认 PonWrt/MD，以 root 登录，镜像初始未设密码时留空，进入后立即设置自己的管理密码。
    2. 打开“网络 > PON > 配置”，Line mode 填现网实际模式。按第 01 步记录填写真正用到的 SN/Registration-ID、LOID/密码；按页面分栏填写，不把这些字段互相混填。
    3. 保存并应用。需要时通过 PuTTY SSH 22 登录 root，执行下面重启 PON 命令让线路模式/身份生效；此时不再使用原厂 Telnet。

    通过后：配置已保存，光纤未接时 LOS/未注册属正常，继续切换光纤。

    不符合时：如果运营商按旧光猫 SN 绑定，需要使用你自己线路允许的已登记身份，或让运营商变更绑定；只换光猫不一定自动注册。

    字段填什么
    Line mode第 01 步确认的实际线路模式，不能凭华为品牌猜
    SN按本线路绑定要求填写；页面支持 16 位十六进制或 4 个厂商字符 + 8 位十六进制
    Registration-ID / LOID / LOID password分别填现网实际认证字段；未使用的字段不从网上复制值
    ONU identity：厂商/设备/硬件/软件/OperatorOLT 要求时按旧光猫实际记录；原页面没有的字段先保留，不能用商品名编造
    OMCC version默认 0xb0；仅确认 Huawei OLT 兼容问题时按上游提示尝试 0x86。旧光猫是华为不代表局端也是华为

    在 PonWrt 的 SSH 终端执行：配置保存后重启 PON 服务

    /etc/init.d/airoha-pond restart

    配置层的线路认证身份与本机 bosa/ri 板级数据分开处理。恢复本机校准后，再按你的现网绑定要求配置认证。

    以设备实际结果为准；遇到异常先按提示处理。

    17 切换光纤，先确认注册

    1. 准备好把光纤接回华为的退路。给旧光猫断电，从它的 PON 口拔下入户光纤，接到新 XG 的匹配 PON 口；两台设备不同时接入同一条线路。
    2. 保护接头，不直视纤头、不强弯；插头或光接口不匹配就停，不硬插。等待并查看 PonWrt 的 PON 状态。
    3. 先看光信号，再看 XG-PON 的 O5/OMCI/认证，或 EPON 对应注册状态；执行下面命令可查看详细状态。

    通过后：光信号正常、注册成功，且协议数据通道已应用后，再设置互联网 WAN。

    不符合时：LOS/功率异常先查光纤和本机校准；O5 但没网先查 OMCI/数据通道，不重刷引导。注册失败且无法解决时按“恢复旧光猫”处理。

pondctl datapath --line line0

    18 配置一体路由的 WAN

    1. “网络 > 接口”编辑互联网 WAN：现网 PPPoE 就填自己的宽带账号密码；IPoE/DHCP 就按实际选择。桥接旧光猫的拨号通常原来在外接路由器上。
    2. 本机默认光纤 WAN 设备是 pon0。只有确认主机侧需要业务 VLAN 时，才在“网络 > 设备 > 添加设备 > VLAN 802.1q”以 pon0 建立实际 VID，再把 WAN 设备选为 pon0.VID。
    3. 若 PON 数据通道已提供去标签的业务，WAN 使用 pon0，不再套一层 VLAN。结合第 01 步原配置与 PON 数据通道状态确认，不能因旧 VLAN 有数值就无条件再加标签。
    4. WAN 归入 wan 防火墙区域，保留正常 WAN 转发/NAT；LAN 提供 DHCP/DNS。保存应用，查看拨号/租约、IP 和 DNS。

    通过后：电脑能打开网页，WAN 获得预期地址；再接回家庭设备。

    不符合时：不知道 VLAN、认证或去标签位置时不能编一个全国通用值；保存状态输出，先接回旧光猫恢复上网，再查明配置。注册成功并不自动证明互联网/IPTV/语音可用。

    PonWrt 可以使用原来的 192.168.1.1，但这时旧光猫已退出家庭 LAN。新系统若有 WAN6，也按原线路方式核对 IPv6；不要只看 IPv4 一次测速。

    以设备实际结果为准；遇到异常先按提示处理。

    19 接回家庭设备，完成验收

    1. 电脑直连测试网页、DNS、IPv4/IPv6和上下行。先确认重启后能重新注册和上网，再做一次断电冷启动测试。
    2. 把家庭设备接到新 XG 的 LAN。若继续用原路由器发 Wi-Fi，把它改为 AP 模式，停用旧拨号/第二个 DHCP，并给管理地址避开 PonWrt；按该路由器 AP 模式要求接线。
    3. 测试 LAN1—LAN4，以及你需要的 IPTV/语音。XG 本身没有 Wi-Fi，不能省掉无线 AP。
    4. 在 PonWrt“系统 > 备份/升级”保存配置备份；连同原厂分区备份、接入记录和本机 bosa/ri 私下留存。

    通过后：PonWrt 已刷入，并在你的运营商线路上完成注册、上网、冷启动和所需业务验收，才算替换完成。

    不符合时：任一核心业务不通，先保留日志并恢复旧光猫；不要靠再次重建 UBI 解决业务参数问题。

    以后升级用匹配 MD UBI/PON 的系统镜像直接刷写系统，不重复重建 UBI、不常规重刷 BL2/FIP。当前构建已含 LAN1 复位修正；千兆电脑测速不能证明 2.5G 上限。

    以设备实际结果为准；遇到异常先按提示处理。

    排查：原厂与备份

    现象先做什么何时停下
    网页打不开 / 打开了华为电脑单独直连新 XG LAN2/3，看 ipconfig 和标签地址，使用 http://。设备身份或管理地址不明时不 Reset。
    169.254 地址核对自动获取，换网线/网口；标签明确时按第 03 步临时设 IP。不把电脑设为光猫相同地址。
    原厂超管登录失败用你已有的本机超管凭据，核对大小写。运营商/卖家可能改过；不为恢复默认先清空配置。
    密码输入没有字符这是 Telnet 正常隐藏，输入正确密码后回车。连续认证失败先停，避免锁定。
    su unknown user / uid 非 0核对 FTP 开关、标签账号及该固件 su 路径。不启动备份或迁移。
    没有 USB_READY / mounts=2两个 .sh 放根目录，换兼容 FAT32/USB2 盘，移除多余盘，看 /proc/mounts。不把 XG_USB_ROOT 改成 /tmp。
    sh 报 \r / syntax error从包内原样重新复制 .sh，避免 BOM/CRLF/.sh.txt。不边改脚本边刷写。
    空间不足 / 只读盘df 检查真实 U 盘容量和读写属性，换有足够空间的盘。不删除光猫系统文件。
    dd 失败 / FAILED.txt保留已生成目录、读日志和 dmesg，查电源/盘和 NAND。不加 conv=noerror 掩盖读错。
    Missing / Length / hash mismatch复制完整目录重验；仍失败就重新读取，保留设备校验单。不修改校验单或 proc-mtd 来通过。

    排查：迁移、启动和 PON

    阶段/现象处理
    Stock2UBI 无法运行 / Exec format error程序运行在新 XG 的 root Shell，确认 aarch64、完整传输、chmod +x；不是 Windows EXE。
    内核不符 / MTD unlock failed保存原错误，不忽略版本检查、不加载未知 .ko。
    3333 不通PuTTY 中程序需仍运行；用新 XG 原厂实际 IP:3333，不用 U-Boot 地址。
    刷引导报部分写入失败保留当前供电/终端和全部错误，不主动重启，先恢复电脑外网求助。
    U-Boot 恢复页不通电脑 192.168.0.2/24，LAN2/3，等约一分钟，打开 http://192.168.0.1。
    FIP / bosa / ri / 系统写入失败停在恢复页，核对文件、来源、长度和包校验；缺 FIP 时不启动，不反复重建。
    Boot system 后 .0.1 不通系统地址变了：电脑改 DHCP，查地址，通常访问 http://192.168.1.1。
    系统起不来但 U-Boot 仍在安装后上电约一秒再按住 Reset 进入该引导 Web 恢复，先查 FIP/板级数据/系统；不要套用原厂 Reset 时序。
    LOS / 光功率 / 校准异常查匹配光纤、接头、本机 bosa/ri；不要借其他机器校准。
    光信号正常，注册失败核对现网制式、实际 SN/认证、OMCI/OAM/OLT 兼容；不凭旧光猫厂商推断 OLT。
    O5/已注册，仍不能上网查 pondctl datapath、OMCI 映射、VLAN、PPPoE/DHCP、DNS/防火墙；不能靠刷引导解决。
    LOID conflict / 认证冲突检查旧设备确已退出该线路和身份/绑定要求；不拿第二个 ONU 同时试。
    只有 LAN1 异常先用 LAN2/3 管理，核对本包 a57faf9 和冷启动结果，保存日志。

    U-Boot 高级页的 RAM boot 可用匹配 recovery.itb 临时救援。“整片恢复”要求实际覆盖范围、坏块/OOB和偏移都匹配；不能把 mtdN 文件拼接，也不能因文件叫 all_flash 就无条件上传整片恢复。

    备用：CH340 串口与传文件

    1. 免拆主线不接 TTL。需要看启动日志时插 CH340/CH341，运行 05-Check-Serial.cmd；无 COM 再安装 drivers/CH340-CH341/CH341SER.EXE。
    2. 确认 TX/RX 是 3.3V TTL。光猫断电后按 PCB 丝印接 GND—GND、适配器 TX—板 RX、适配器 RX—板 TX；VCC 不接，仍用原装电源。
    3. 04-Open-TeraTerm.cmd 选实际 COM，115200、8N1、无流控，先记录启动日志。无输出先查共地和 TX/RX，不接 VCC 试错。

    只有实际日志明确等待 XMODEM 才发送该阶段文件。BL2 请求 FIP 时用本包 MD bl31-u-boot.fip；BootROM 和 BL2 不是同一阶段，不套一个通用发送顺序。

    优先用 U 盘。02-Open-WinSCP.cmd 连接原厂时按已启用的 FTP 账号设置，FTP 21 端口；06-HTTP-Transfer.cmd 是依赖本机 Python 的备用传输；07-Open-Tftpd64.cmd 移动目录后需重选 tftp-root 和直连网卡。

    替换没成功：接回旧光猫恢复上网

    1. 若还停在新 XG 原厂备份阶段，直接把电脑网线接回原网络即可；无须重置任何光猫。
    2. 若 PonWrt 无法替代，给新 XG 断电，把入户光纤接回原华为，给华为通电，恢复原来的家庭接线。
    3. 如果改过旧路由器 AP/拨号设置，按之前保存的记录恢复；先不改华为的原始认证。
    4. 电脑 ncpa.cpl 恢复原 IPv4/DNS 设置，原来 DHCP 就自动获取；测试原网恢复。

    这是恢复现网的接线方法，不是把新 XG 整片刷回原厂。若新 XG 正在写入或刚报告部分写入错误，先保持它的供电/恢复会话、保存日志，只将电脑恢复到可联网环境求助。
